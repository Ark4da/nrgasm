# M0–M1: Setup + One Card Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:executing-plans in **teaching mode**, as defined in `CLAUDE.md`.
>
> - **🧑 steps:** the owner writes the code; Claude explains, gives hints, and reviews.
> - **🤖 steps:** Claude writes the file and explains it.
> - **Commands:** the owner runs every command, in PowerShell on Windows.
>
> Track progress with the checkboxes (`- [ ]`).

**Goal:** A Vite + React + TypeScript project on localhost that shows one static Mango Loco card styled as design D, "Acid Lab".

**Architecture:**

- **Data.** A typed catalog in `src/data/cans.ts` and a demo `TastingEntry` are passed as props to `CanCard`.
- **Components.** `CanCard` is built from two small display components, `CanPlaceholder` and `StarRating`.
- **Styling.** Each component has its own CSS module, and every color, font, radius, and spacing value comes from `src/styles/tokens.css`.
- **No state yet.** There is no state, storage, or routing until M3 and M4.

**Tech Stack:**

- Vite 8 with the `react-ts` template (needs Node.js 20.19+ or 22.12+);
- React + TypeScript, `strict`;
- CSS Modules;
- Google Fonts: Archivo and JetBrains Mono.

**Spec:** `docs/PRODUCT.md` (data model, M0 and M1 criteria) and `docs/DESIGN.md` (tokens, CanCard anatomy). Rules: `CLAUDE.md`.

## Global Constraints

- TypeScript `strict: true`. No `any`. Type-only imports use `import type`, because the Vite template enables `verbatimModuleSyntax`.
- No raw hex values in components. Every color comes from a token in `src/styles/tokens.css`. The only exception is `Can.flavorColor`, which is data.
- No new dependencies in M0–M1 beyond what the Vite template installs.
- Code, identifiers, comments, and UI copy are in English. Commit messages follow the `type: summary` form (`feat:`, `chore:`, `docs:`, `style:`).
- Use no Monster logo, claw mark, or can artwork. The can is the CSS placeholder.
- Never invent product facts. Leave `caffeineMg`, `sugarG`, and `volumeMl` out unless the owner has verified them.
- Text contrast is at least 4.5:1. `--color-text-disabled` is never used for readable text.
- Respect `prefers-reduced-motion: reduce`: no hover transition animation.

## Review Focus

These are not covered by automated tests in M1. Each one is checked by hand in the task named.

1. **Unknown facts.** A can without `caffeineMg` or `sugarG` shows "—", never "undefined mg" or "NaN". Checked in Task 6.
2. **No rating.** With `rating: null`, the card shows five empty stars and the label "Not rated", never "null / 5". Checked in Task 5.
3. **Untried can.** With no `entry`, the card shows no "Tried" mark and no note block. Checked in Task 6.
4. **Phone width.** At 390px wide, the card's two columns stack and nothing scrolls horizontally. Checked in Task 7.
5. **Long names.** A long name such as "Ultra Strawberry Dreams" wraps inside the card without overflow. Checked in Task 7, using a temporary edit.
